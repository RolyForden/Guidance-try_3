# 实验设计与筛选

> 先审 baseline，再用 20% 完整筛选平台快筛多个成熟实现找涨点；失败先定位，全量只做确认。

## Baseline：先理解，再证明链路可信

只优先选择代码、数据和评测入口可核验的 baseline。在提出改进前，先读懂整体框架、每个模块的职责与输入输出、训练协议和评测路径，明确 baseline 已解决什么、在什么可观察条件下仍然不足。执行顺序：

1. 固定官方仓库 commit、checkpoint、数据来源和校验值。
2. 先跑单样本，检查输入、输出、NaN/Inf 和 shape。
3. 在固定筛选子集上同步训练 baseline，建立与候选方法相同协议下的可靠参照。
4. 候选通过筛选后才投入完整 split 或完整训练。
5. 与论文数字比较时必须使用相同 setting 和 evaluator；差异只报告，不靠换配置追平。

baseline 能运行不等于完整复现，smoke test 能运行不等于方法有效。若为跑通而修改核心实现，不能继续称为官方复现。

## Smoke、筛选与 Full

### Smoke test

极小 batch 或单样本，只检查数据、前向、反向、保存和评测链路。通过标准是“能正确运行”。

### Screening experiment

20% 左右的固定子集不是只跑几轮的预实验，而是候选方案的完整筛选平台：

- 按 shape、对象或研究单位采样，而不是随意抽 annotation；
- 冻结 seed、清单和采样规则；
- 报告分母、类别覆盖和缺失类别；
- baseline 与候选使用同一子集、固定 validation 和相同 evaluator；
- baseline 与候选均训练到基本收敛，不能以 2–3 个 epoch、单个偶然 checkpoint 或极小涨点决定去留；
- 方案选择、超参数调整和 checkpoint 选择在训练数据内部完成，官方 test 保留到最终方案冻结后；
- 候选优先来自能替换 baseline 同一职责的成熟机制；允许准备多个实现，但每次比较必须说明唯一核心变化和必要对照；
- 预先写明继续、补证和停止表现，并同时观察主要指标、误报、稳定性和实际效应大小。

子集失败不构成大方向失败的数学证明，子集成功也不能替代全量论文证据。它只决定当前实现是否值得放大。一个大方向应允许若干有机制依据的实现，例如同一“任务查询驱动的局部证据”可以由查询瓶颈、动态路由、跨注意力、检索或几何匹配实现；一种实现失败时，先定位失败环节，再决定替换实现还是停止方向，不能无限换模块，也不能一次失败就结束方向。

已有工作触及某个 gap，不自动消除继续研究的价值。可以改变有真实意义的应用条件、数据条件、监督方式、网络位置或实现机制。优先考虑 baseline 未覆盖的真实复杂条件，例如遮挡、退化、跨域、模态缺失、测试时分布偏移、视角不一致和标注稀缺；这些条件必须有实际意义、公开数据和可复现实验支撑。跨领域迁移也可以构成贡献来源，但每个迁移都必须说明它解决 baseline 的哪个具体不足，并用简单对照排除收益只是额外参数、更多监督或更多训练预算。

### Failure diagnosis

实验失败时，依次检查：方向假设是否缺少可识别信号；观察或输入是否暴露了所需信息；表征是否适配任务；模块是否放在正确位置并被实际利用；监督信号是否匹配目标；代码与数据对应是否正确；超参数与训练是否足够；数据划分、指标和 checkpoint 选择是否公平。记录支持与反对每种解释的证据，不把所有失败归结为方向错误，也不靠事后换指标把失败改写为成功。

实验结论始终分成三层：代码已经实现并跑通；方案相对匹配 baseline 有效；方案达到或超过现有强方法。实现不等于有效，局部涨点不等于达到 SOTA。

### Full experiment

只有在筛选集上相对同步 baseline 获得稳定、明显且可解释收益的候选才跑全量。全量是确认阶段，不是继续探索结构和超参数的场所；训练前应冻结模型结构、损失、超参数和训练协议。正式结果应覆盖强 baseline、简单机制 baseline、必要消融、公平性、效率、失败分析和研究问题要求的泛化。

正式 20% 候选筛选与全量随机训练至少使用两个训练 seed，分别报告并冻结统计协议，与实验模板一致。单 seed 只可用于获批的 smoke 或工程预检，不决定候选是否放大；底座原样复现遵循论文协议。不能通过反复换 seed 挑最好结果。

模块数量不是创新性。简单方法若已带来可靠收益，可以再用近期工作做机制增强；复杂结构只在明确诊断或已有收益支持时进入，不能用 fancy 结构掩盖没有实际收益。训练运行期间并行准备下一候选、数据检查和配置审计，避免 GPU 空等，但不增加无助于判断的记录层级。

## 探查式实验 vs 筛选实验

| | 探查式 / 理论上的实验 | 筛选实验（默认） |
|---|---|---|
| 回答的问题 | 某机制/信号“是否存在、是否成立” | “哪个实现能涨点” |
| 手段 | 诊断、探针、线性可读性、消融 | 多个成熟实现 × 20% 训练到收敛 |
| 产出 | 支持/否定某假设 | 某实现相对 baseline 稳定提升 |
| 失败时 | 得到一个负结论（写不成论文） | 换下一个实现（常态） |

博士的判断：**理论推导只在讲故事层面有用；这是实验学科，能涨点的实现才算数。**

三问自测（任一答不上来，就可能是探查式）：
1. 这实验成功了，我接下来**发哪个实现**？
2. 它失败了，会改变我**用哪个方法**吗？
3. 它在**训练一个方案、和 baseline 比涨点**吗？

用途：探查式**只**在 ① 极便宜的必要条件检查、② 已筛出涨点后解释机制 时用，不用它替代筛选。

## 便宜的必经性检查：oracle 反事实（筛选之前）

在投入 20% 筛选前，机制型课题先做一次**最便宜的必要条件检查**：

- 把**最乐观上界**（oracle 帧 + oracle 裁剪/放大）与**同预算匹配对照**（整图 / 整图 + 位置提示 / 仅几何·文本先验）在**同一模型、同一帧、同一文本、同一输入与计算预算**下配对比较；
- 上界无增益 → 机制第一环不成立，**停**；上界有增益、匹配对照追不上 → 证据干净，进筛选；
- 这一步是探查式的**唯一合法用途①**，产出是“这条链要不要继续”，不是“哪个实现涨点”。

### stop / go 必须可执行

- 预先定义**困难子群**（如目标投影面积小 / 遮挡高 / 多候选部位），**不按结果事后挑类别**；
- **≥2 seed 或 2 模型**；paired difference + bootstrap CI；
- 要求“**增益在预定义困难组明显更大**”，而不只是总体为正；
- 同一现象在 2 个 seed / 模型都不出现 → 判该路线停。即使结果负，也算真正结束了一个问题，而不是又一个“未判定”。

### matched baseline vs SOTA

机制验证要的是**强而可复现、且能做严格配对干预**的基线，**不是排行榜第一**。明确边界：不声称 SOTA improvement，只声称“同一 backbone / 同一输入 / 同一训练预算下，加入某信息产生了什么变化”。**不可运行的近期方法放进 related work / limitation，不当前置依赖。**

## 两个硬证据：锚（前）与判死（后）

| | 证明什么 | 时机 | 需要什么 |
|---|---|---|---|
| **锚** | 问题/失败真实存在 | 造机制**之前** | 观测 + 可量化 + 可复现 + 排除简单解释 |
| **判死（否方向）** | 方向该埋 | 做了机制**之后** | 多个**异质**实现共同失败 + 排除实现/训练/协议 |

失败信号“没涨点”有四种原因（靶假 / 箭钝 / 测坏 / 训练不足）；**没有前锚就分不清，也就做不了后面的“判死”。**

## 一次实验 = 一份冻结记录

正式筛选（20% 及以上）开跑前，**必须**用 `templates/experiment.md` 把 §1 预注册、§2 对照矩阵、§3 统计协议、§5 自检填死；**填不出 = 判据未定，不许开跑。** agent 自动起草见 `templates/experiment_kickoff.md`。

最低要求：**对照矩阵**（主基线 + 最简对照 + 朴素聚合 + 候选 + ≥2 负控制 + 参数预算匹配，缺项写理由）；**统计协议**（配对 / 簇单位 + bootstrap 次数 + seed + CI）；**运行记录**（run_id、工程失败与科学结果分开）；**判断**（三层 + 失败定位 + 边界）。

## 实验的最低可追溯性

每个真实实验至少保留：

- 实际命令、冻结配置和代码版本/快照；
- 数据划分或样本 manifest；
- 数据和 checkpoint 校验值；
- stdout/stderr、机器可读指标和原始输出路径；
- 运行时间、显存及协议偏离；
- 失败结果，不覆盖、不静默删除；
- 图表对应的原始数据和生成脚本。

外部算力执行者只执行和交付，不替主研究者 commit、选择指标或解释论文主张。

## 实验设计与止损

### 横向 baseline

博士建议从开源候选中横向跑多个模型，经验目标约 10 个，再选性能和可修改性较好的主 baseline。实际数量服从同任务兼容性、权重可得性和时间，不能为了凑数重实现不可比模型。

### 单样本 -> 20% -> 全量

> 〔会议〕“先抽 20% 的数据来做，为什么 20% 就是快速验证。”

执行顺序：

1. 单样本检查输入输出；
2. 10%/20% proxy 快速筛选；
3. 通过者再跑全量确认。

20% 是优先级很高的实操纪律，但不是科学定律。子集需冻结采样规则、报告类别覆盖和分母；缺失类别时不能把子集数字当完整复现。

### 让模型收敛

> 〔会议〕“让它们收敛，而不是固定的 step，就是想看出真正有潜力的是哪些模型。”

训练候选的筛选应比较收敛趋势，不应因统一固定 step 错杀收敛速度不同的方法。

### 模块化消融

每个关键机制都要有最简单去除版本。加模块后变差，就接受模块不成立；不能通过换指标或隐藏负结果维持故事。

### 随机种子的冲突

博士原话：

> 〔会议〕“只要审稿意见里面出现随机种子，就一定是 AI 审稿，正常人不会做这个实验。”

本汇编忠实保留该观点，但项目仍需记录 seed，禁止挑 seed。执行口径以本文件前述随机性纪律为准：正式 20% 筛选至少两个训练 seed；不能以这段历史经验放宽模板门槛。

## 算力与租卡实操

- 本工作区算力与费用默认不作硬边界，不以报价或费用上限阻塞推进；超时仅用于防挂死。实验协议审批、对照公平性与 test 封存仍照常执行。
- 无卡模式约 0.1 元/小时，可用于写代码和下载；
- 4090 经验价格约 2.88 元/小时；
- 西北/北京 B 区卡多，V48 可提供 4090 核心与更大显存；
- CPU 核数多有利于数据加载；
- 可克隆实例切换 GPU，永久盘保留关键环境和结果；
- 大文件使用断点和分块并行传输；
- GPU 阶段提高利用率，实验结束及时关机；
- 让 Agent 预估时间、监控、保存日志和关机，但不交出账号凭据；
- 经验预算“一两百元完成一篇 CCF-C 实验”只作成本参考，不是结果保证。

## 博士论文方法论补遗（实验）

### 实验：先手工 baseline 建立设计规则，再上深度模型

Thomas 的手工 pipeline 实验结论（半径邻域优于 KNN、网格降采样控密度）直接变成网络设计选择。这是「20% 子集先筛」的变体：**先用手工 baseline 得到确定性设计规则，再把结论喂给深度模型**。

### 指标与 baseline：覆盖泛化 / 效率 / 鲁棒三个边界维度

不只测主任务精度：Yue Wang 测 unseen/noise/transfer，Thomas 测 model size/speed，Chang 测不可靠通信。指标额外覆盖**泛化、效率、鲁棒**，服务于 RQ 而非只报主精度；baseline 也要覆盖**非学习 + 学习**两层（手工特征 baseline + deep SOTA），不能只挑好打的。

## Baseline 审计清单

1. 官方代码、commit、权重和数据来源是否明确？
2. 数据、checkpoint 和交付包校验值是否一致？
3. 单样本输出的 shape、范围和 NaN/Inf 是否正常？
4. 子集是按研究单位抽样还是随意按 annotation 抽样？
5. 包装器是否改动 forward、dataset 或 evaluator？
6. `missing_keys` 与 `unexpected_keys` 是否准确解释？
7. 日志、JSON、报告和运行时间是否一致？
8. 声称的复跑、after hash、编译成功是否有原始证据？
9. 是否区分 smoke、20% 工程筛选、完整 split 复现和论文数字一致？
10. 环境安装失败是否被无 `set -e` 的脚本掩盖？

## 结果与机制审查

正式结果进入论文前检查：

- 单 query 本来错误的样本是否被误当作 switching failure；
- GT 本身几乎相同是否被误读为预测不敏感；
- 类别、面积、共现和词汇模板能否解释现象；
- 选择层、阈值和样本是否使用了测试结果；
- 图表是否能回到机器可读原始文件；
- 负结果和协议偏离是否完整保留。

表示差异、probe 可读和 activation patch 成功不自动等于忠实机制。机制主张至少联合考虑 clean-run signal、双向 restoration、correct-case destruction、随机/错位/同义控制和 held-out 预测。恢复成立而破坏不成立，只能称充分或替代路径；表示可读但干预无后果，只能称相关现象。
