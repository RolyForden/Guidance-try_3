# 选题与立项

> 从真实 failure 收敛到值得做的 gap：方向红线、查重与窗口、gap 锋利度、可行性与资产、立项审计。

## 一句话方法论

先锁定真实问题和最近邻证据，再写方法；先用低成本实验淘汰方向，再投入完整算力；先让主张经受反驳，再写论文。

Codex 的价值不是“替人做科研”，而是把人的会议经验、方向感和风险偏好变成约束，再承担搜索扩展、工程执行和材料整理。人仍必须决定：该怀疑什么、什么证据足以继续、何时停止，以及哪些结果在审稿语境中站不住。

## 选题：约束先于搜索

选题前先写清：

- 目标 venue、年份、track、页数和截止时间；
- 公开数据、开源代码、硬件、预算和最长训练时间；
- 合作者、作者贡献和不可触碰的方向；
- 论文服务的长期能力，以及只为短期投稿服务的技巧。

这些约束把“什么最热门”改成“什么在当前可行域内最值得做”。信息不全时先补会改变结论的缺口，不急着写代码或命名方法。

### 广搜和深挖分开

1. 广搜阶段追求召回：目标会议近年题目、跨会议代表作、数据、代码和算力地图。
2. 深挖阶段追求证据：最近邻全文、方法与实验章节、官方代码、数据划分和真实限制。
3. 只让少量候选进入深挖，避免对每个方向都建立庞大文献工程。

近期强方法适合竞争性比较；简单或经典方法适合机制对照。不能因为模型老就机械排除，也不能因为模型新就默认更强。

论文是压缩的结果，只给结论、不给思考过程。选题与实验的方法论要去读**硕博毕业论文（尤其博士）**的以下章节，它们是论文里看不到的富矿：

- **选题章**：作者怎么从大方向收敛到具体 gap、怎么查重、怎么判断「值得做」。
- **文献综述章**：作者怎么梳理一条领域脉络——这是「研究脉络 / 时间线」的现成范本（比零散文献矩阵更能暴露前沿 gap）。
- **实验设计 / 消融 / 局限章**：实验怎么设计、消融怎么取舍、负结果怎么处理、局限怎么诚实写。

读这些章节是为了「筛选出有用信息，厚实自己的规则」，把它们当作与顶会论文并列的调研来源，而不是只看 paper。

### 判断方向所处阶段

不要只数论文数量。至少判断：概念提出期、快速扩张期、同质化期还是成熟期；代表工作解决了什么；剩余失败是否可测；代码和数据是否足以支撑本科生周期。

完全没人做可能是伪需求，太多人做可能已拥挤。较好的窗口通常是：任务已被证明重要、公开资产可用、具体机制问题刚开始有人触及。

### 主动攻击模型偏好

当模型反复推荐置信度、可靠性或热门模块时，主动追问：

- 这是任务真实矛盾，还是生成模型习惯性的安全答案？
- 最近工作是否已经直接覆盖？
- 为什么简单 baseline 不够？
- 什么结果会让我们放弃？

每个候选都要经过一次“为什么不该做”的独立审查。对话评分只能用于候选排序，不能解释为录取概率。

## 从 gap 到候选 idea

一个候选至少包含：

```text
研究问题：要解释或改变什么现象？
可观察失败：现有方法在什么条件下失败？
机制假设：为什么发生？
最小实验：最便宜的决定性证据是什么？
最近邻：最可能覆盖主张的工作是什么？
简单替代：crop、重加权、普通 loss、强 baseline 能否解释？
资产：数据、代码、权重、算力和周期。
否定条件：什么结果出现就停止或降级？
拒稿攻击：审稿人最可能提出哪三个问题？
```

“创新是排列组合”只能作为工程启发。有效组合或迁移还必须回答：源问题与目标问题共享什么结构、假设哪里不同、为什么适用于当前失败、需要重新验证什么。成熟模块可以降低实现风险，不能保证组合有效或论文成立。

探索性实验可以帮助形成假设，但最终主张必须在独立样本或冻结协议上确认。不能先跑出模块，再从多篇论文中拼动机。

### 课程中的具体例子及正确解读

- Vision Mamba 的扫描顺序向低层视觉、遥感和高光谱迁移，说明“改变基础机制 + 找任务适配”可以形成早期窗口；不能简化成任意换扫描形状都能发表。
- PConv、AKCMamba-YOLO 等例子表面像换模块，正式工作还包含任务动机、结构设计、效率论证和多数据实验；课堂直觉不能替代完整证据。
- 点云恢复方向从置信度地点识别转向复合退化，说明候选排名会随查重和导师反证改变；早期高分不是方向成立。

## 锚：先找靶，再射箭

**靶 = 要解决的问题（那个失败）；锚 = 钉住靶的那组硬证据（证明这个问题真实存在）；箭 = 方法 / 机制。锚属于“靶”这一侧，不属于“箭”。顺序永远是：靶 → 锚 → 箭。**

两条失败对这条链：**缺锚** = 有靶、没证据（靶是纸糊的）；**为箭找靶** = 先有箭、再找靶（顺序反了）。

> 我在 ___ 上，亲眼测到、反复测得到、而且换个现成简单办法也消不掉的那个失败。

四个条件：
- **真实**：观测到的，不是推理出来的。（“全局特征粗 → 细区域差”是推理；“在 LASO val 上 POS 区域 MAE=0.117”是**跑出来**的观测。）
- **可量化**：有一个会涨/跌的数（MAE、IoU），否则不知道自己在不在进步。
- **可复现**：固定数据 / 权重 / 脚本能反复测到，别人也复现得出。
- **排除简单解释**：不是“工程没做好”，而是真缺口——最便宜的替代（crop、高分辨率、打乱对应、先验、训练加长）都消不掉。**机制型课题里，这一条落地为「在匹配对照下消不掉」**（如 location-cue、geometry/text-only 等**同预算**对照）；**不必**在动手前穷举所有现成方法。

**“硬”不等于“贵”**：锚常常零训练、纯统计（如 pair 存在性）+ 一次 prompt 诊断即可。

30 秒自测：能不能写出「在 ___ 上，___ 方法在 ___ 条件下，___ 指标是 ___，而且 ___（最便宜的替代）消不掉」？写不出、只能写“因为现有方法……所以我们需要……”——还在为箭找靶。

- **没锚**：“我们要引入局部视觉，因为全局观察对细区域不够” → 故事，失败了也不知道为什么。
- **有锚**：“在 LASO val 上，GEAL 对 target_mass≥0.01 区域 MAE=0.117，且分辨率翻倍只降到 0.114（没差）——缺口不是分辨率” → 靶。

### 四层：靶 / 箭 / 实现 / 实验设计
- **靶**：研究问题 / 要解决的 failure；
- **箭**：机制（idea 层面）；
- **实现**：机制的一种具体写法；
- **实验设计**：怎么测箭有没有射中。

复盘时**标明动的是哪一层**；一个**实现**失败只否实现，不否**方向**。**判决方向（靶的生死）不能由理论下、要由实验下**——用“去术语测试”给方向判死刑，本身就是“理论推导/讲故事”。

**前锚、后判死**：锚在造机制**之前**（证明问题真实）；“判死方向”在**之后**（证明方向该否），详见 `02_实验设计与筛选.md`。没有前锚，后判死做不了——“没涨点”有四种原因（靶假 / 箭钝 / 测坏 / 训练不足），没锚就分不清。

### 机制型课题：把路线拆成假设链，先冻结下游（H1/H2/H3）

一条“机制路线”通常含多个**递进假设**。例：FocalAfford 的“高分辨率局部观测 → 整物体上下文 → 特定蒸馏” = **H1**（局部观测本身有增量）/ **H2**（相同局部信息下，全局上下文还有增量）/ **H3**（前两者成立后，特定蒸馏优于普通蒸馏与重加权）。

- **在 H1 没被稳定验证前，不要用 H2/H3 的最终方法形态去寻找“值得它解决的问题”**——那正是「先有技术路线、再回溯找问题」（FP-001）。
- **做法：冻结 H2/H3，只对 H1 做最强的反事实检验**：先把**最乐观上界**（oracle：真值选帧 + 真值裁剪）喂进去，看模型**到底会不会利用**这块真实局部信息。连上界都没增益 → 自动选帧 / 上下文 / 蒸馏可直接停。上界有增益、而“整图 + 位置提示”追不上 → 才拿到干净证据：**增益来自局部辨识，而非空间先验**。
- **换数据集 = 换了被测量的对象（estimand）**：核心科学问题可能不变，但操作化研究问题（“局部”的定义、可用视觉、遮挡、视角、输出空间）已变。连续换载体容易变成“每个数据集都做一点、没有一个真正检验 H1”。

### “方向没问题”要问是哪一层

把“方向”拆三层回答，别把“整条路线”和“科学问题”混为一谈：

- **科学问题层**：问题本身成不成立；
- **技术路线层**：这条机制链（含 H1）有没有证据成立；
- **实验搜索策略层**：是在“可控载体上对 H1 做反事实检验”，还是在“换 benchmark 找一个能支持路线的失败”。

常见组合：**科学问题层成立 / 技术路线层未成立 / 搜索策略层有问题** → 不放弃方向，但**放弃对整条路线的承诺**，把它压成一句最窄的问题先打穿。

### 论文底座（参照锚）：先扎一两篇论文

“锚”有两种口径，**别混**：

- **实证锚（失败证据）**：真实、可量化、可复现、匹配对照下消不掉的 failure——回答“**要解决什么**”。
- **参照锚（论文底座）**：一两篇**真正读懂、能复现、能逐模块解释**的论文——回答“**站在什么上面做**”。

两者**配套、不能互相替代**：没有参照锚，工作会“**飘**”——每一步都顺手对到某篇论文，却没一篇当底座；没有实证锚，就会“为箭找靶”。

**做法（开工前写死一句话）**：

> “我以〔论文 A〕+〔论文 B〕为底座；我复现它到〔量级〕；它的〔具体 limitation〕是我的起点；我的对照是它。”

- **选 1–2 篇，读到底**（任务定义、方法、实验协议、代码、限制全吃透）。**优先选“新 + 开源 + 顶会（A 会）”的**：新＝窗口还没过、开源＝能复现、A 会＝有分量。**广读三四十篇**用于“抽象方法族”，**扎底座要 1–2 篇读透**，不是广读。
- **起点从论文的 limitation 来**：这天然治“为箭找靶”——起点从“我有个 idea”变成“**这篇论文在某处不行**”。
- 写不出上面那句话，就**不开工**——别让 agent 用下载 / 审计 / 探针**代替研究理解**（那会把模糊问题拆成一堆流程，看起来在推进，判断却没收敛）。

**“读透”的通过标准（缺一即未读透）**——1–3 = 读懂，4–6 = 能开工：

1. **能复现**：到报告量级；给出「我的数字 vs 论文数字 + 差异」；
2. **能拆解**：数据 → 模块 → 损失 → 训练 → 评测，每个模块的 **I/O + 职责**；
3. **能解释 why**：每个关键设计回应哪个 failure；**去掉会怎样**（引它的消融）；
4. **能定位限制**：说清它在**什么条件下不行** + 证据；
5. **能对齐口径**：baseline / 指标定义 / 数据划分 / 空值处理；
6. **能延伸**：我要改哪一处、为什么、用什么最便宜的对照测。

⚠️ **只到 1–2 不算读透**——那只是“审计它能不能跑”。

**产出**：一份 **底座档案**（`templates/base_paper.md`，≤1 页 + 一份可运行复现）。**写不出第 5–6 项 = 还没到“能开工”**；agent 起草走 `templates/base_paper_kickoff.md`。

这里的“不开工”指不进入候选方法实验，不禁止获批的底座复现。先起草项目 `idea/base_paper_<简称>.md` 与复现协议，自己的数字未知就标“未运行”；用户确认后复现、补齐档案，再审批候选实验。阅读量、底座完成标准和候选开跑门槛不变。

> 来源：杜拜想睡觉 2026-10-06——“应该要依靠一两篇论文作为我们的锚点去做的”“太飘了，没有自己的想法”。

### 从底座论文的“盲区条件”找靶（杜拜想睡觉 2026-10-07 recipe）

把“论文底座”落到**怎么找到靶**，一个可执行的三步：

1. **读懂底座**：它的框架 + 每个组件**默认了哪些“干净 / 常规”前提**（如：假设干净图像、单一模态、同分布、充足标注、固定视角）。
2. **列“盲区条件”**：问自己 / 让 agent 问——真实世界里它**没考虑过**的复杂条件有哪些？常见清单：
   恶劣天气（雨 / 雪 / 雾）· 极端光照（夜 / 逆光）· 标注稀缺 · 测试时分布偏移 · 模态缺失 · 跨域 / 跨传感器 · 遮挡 / 密集小目标 · 运动模糊 · 视角剧变 · 时序 / 视频 · 指令歧义。
3. **筛 → 选 1 个 → 设计 1–2 个模块**：
   - **硬筛**：必须**真实** + **有公开数据集能跑实验**（故事再好、没有公开数据 = 直接淘汰）；
   - 选 **1 个**条件，围绕它设计 **1–2 个模块**，让这个条件成为论文的**动机和主要条件**（不是堆模块，是有主题的 1–2 个）；
   - 依据：底座的组件都**没为这个条件设计过**，所以它**正好是盲区**——模块缓解它，提升 + 动机 / 消融都顺。

> **范本**：CLIP + 测试时分布偏移 → 贝叶斯测试时自适应（CVPR25）；SAM2 + 医学少标注 → 在线少样本学习（AAAI26）。

⚠️ **关键边界（FocalAfford 的教训）**：这是**候选靶的生成启发式**，**不是已证的靶**。“baseline 没为这个条件设计过” **≠** “它一定失败”。**先按 `docs/02_实验设计与筛选.md` 做 oracle / H1 必经性检查**，证明这个条件**真失败、且抗便宜替代**，再上模块。**别把“大概率能涨”当“已证成立”。**

> 来源：杜拜想睡觉 2026-10-07——“找一篇新开源 A 会当 baseline，读懂……找它没考虑过的真实复杂条件……挑一个设计一到两个模块，让这个条件成为动机和主要条件”；“性能不用太担心”（但要真实、有公开数据集）。

## 起点的选择：不是必须起于失败，但必须有锚

**不必须从失败出发。** “从失败出发”是最好用的**默认**，不是铁律。科研的起点有多种：

1. **失败**（problem-driven）：“X 在 Y 条件下不行” → 修它。
2. **新能力**（capability）：“新工具能做人做不到的事” → 用它。
3. **新机会**（opportunity）：“新数据 / 新场景” → 建它。
4. **好奇心**（understanding）：“为什么 X 会这样” → 搞懂它（分析论文）。

**但真正的要求不是“起于失败”，而是“最终落到一个可测的缺口上（锚）”。**
- 失败，只是最容易拿到锚的那条起点；
- 从任何地方起步都可以，但必须让这条路最后落到一个“真实、可量化、可复现、简单办法消不掉”的缺口；
- 落不到 → 你没法证明在进步，也没法解释为什么会失败（= 没锚 → 只能换方向）。

不同起点的代价：
- **失败起点**：自带锚，最省力，审稿人天然信服；
- **能力 / 机会起点**（“有新工具就去找任务套”）：容易变成 tool-driven = **为箭找靶**，必须额外花力气造锚；
- **好奇心起点**：分析论文，适合硕博、长周期；本科出**方法论文**很难，容易滑成“讲故事”。

**对短周期、要出方法论文的课题：默认从失败出发。** 若偏要从别的起点出发（比如很喜欢某个机制），就得**额外造锚**；造不出来，就还是为箭找靶。

## 设计方法：先读该数据集的 30–40 篇，抽象方法族，再设计（博士经验）

> 来源：博士 2026-10-02 截图。

- **baseline 往往只有一个**（如 UNet / 官方 baseline）：先把底座认准。
- **读这个数据集上的三四十篇文章**：看大家在底座上**加了什么、为什么这么加**，把**一类方法思路**总结出来。
- **再设计你自己的**（参考成熟工作）。
- 反面：只做“在 a+b 的文章上再叠一个 b(d”——只堆模块、不看动机，**编辑看了就烦、不愿送审**。

**怎么和「先立锚」配合（否则会退化）**：
- 这条是**设计“箭”的方法**，建立在**已经有“锚”**之上：先钉住 failure，再读文献设计。
- “看**为什么**这么加”必须落到 **failure / 动机**；只收“加了什么模块”= 为箭找靶。
- “总结一类思路 → 再设计”要防**排列组合**：每步先问“它回应哪个 failure、有没有成熟替代”（呼应「锚」与「去术语测试」）。
- 顺序：**靶（锚）→ 读该数据集 30–40 篇（加什么 + 为什么）→ 抽象方法族 → 设计箭 → 多实现快筛**。

## 证据与文献

- 摘要用于筛选，方法细节和新颖性判断回到全文或官方代码。
- 论文存在、方法细节正确、代码可用、实验可复现是不同层级的事实。
- 文献记录只保留会改变核心主张的证据；不为数量维护庞大矩阵。
- 无法获取全文时明确写“未核实”，不根据标题补全机制。
- 导师意见属于经验判断；若同时有论文、代码或实验支持，再升级为可核实事实。

## 使用边界与优先级

标记含义：`〔转写〕` 为讲座原话，`〔截图〕` 为截图 OCR，`〔会议〕` 为 baseline 实操分享，`〔Idea报告〕` 为 idea 报告范式，`〔SCI审计〕` 为证伪式任务书。

### 外部材料及可靠性

| 来源 | 级别 | 用途 |
|---|---|---|
| Keshav, *How to Read a Paper* | A，全文已核 | 三遍法与文献调研 |
| NeurIPS 2024 Reviewer Guidelines | A，官方全文已核 | 审稿维度、可复现和 limitation |
| Karpathy, *A Survival Guide to a PhD* | A，全文已核 | 写作流程、截稿和单一主线 |
| SPJ, *How to Write a Great Research Paper* | B，官方页面已核、PDF 未核 | 写作与表达技巧 |

匿名中文博客和营销转述不进入规则。

### 优先级

1. 用户对当前项目的明确决定；
2. 博士针对本科生、短周期、公开数据和有限算力的经验；
3. 导师针对当前 proposal 的 gap 判断；
4. 官方政策、论文正文、代码、数据和真实实验；
5. 外部通用经验。

经验决定先做什么，真实证据决定能声称什么。任何经验都不能被写成实验结果。

## 方向红线

命中以下情况，优先否决或要求换问题：

### 置信度/可信泛化

凡核心贡献只是判断输出是否可信、何时拒识、风险是否受控、是否做置信度校准，应高度警惕。

> 〔截图〕“AI 有一个通病就是喜欢置信度研究，自查是否陷入。”
> 〔转写〕“很喜欢做一些置信度可信相关的一些方向……它无论什么方向，它都说这一个置信度它就一定是有问题的。”

这不是说可信研究永远无效，而是不能把它当成任何任务都适用的默认创新。

### 已被最近工作覆盖

统一恢复、混合退化、输入质量自适应、轻量化等表述若已被直接研究，不能通过换名继续主张新问题。“轻量”通常只是属性，不自动是科学创新。

### 讲不清动机的模块拼接

> 〔转写〕“缝模块的方式最危险的点就是缝合模块，你自己讲不清楚自己为什么要缝。”

若方法去掉术语后只剩“模块 A + 模块 B + loss C”，而每个部件都可被成熟 trick 替换，应先回到问题，而不是继续加模块。

### 常见伪创新黑名单

〔SCI审计〕特别禁止：

- 只把预测器换成 LSTM、Transformer、XGBoost 等；
- 只把优化器换成 PSO、GA、GWO 等元启发式；
- “算法 A + 算法 B + MPC”的机械拼接；
- 加入 CVaR、DRO、鲁棒优化或强化学习就宣称创新；
- 把工程复杂度等价为学术创新；
- 把预测精度提升直接等价为下游价值；
- 未经检索使用“首次、鲜有研究、现有工作很少考虑”；
- 为提高档次人为堆叠多个高级模块。

## 选题：查重、窗口与会议

### 先回答有没有人做

> 〔截图〕“你们有验证过这个方向是不是别人做过的吗？”
> 〔转写〕“如果是完全没人做，肯定也是不行的；如果太多人做也是不行的。”

完全没人做可能意味着伪需求；太多人做意味着同质化。优先寻找“刚开始有人碰”、已有任务价值与公开资产、但具体失败尚未解决的中间地带。

### gap 必须一句话说清

> 〔转写〕“我每次都要问 gap 究竟是什么？它给我们提供了一个很强的动机。”

一句话应包含：现有方法、可测失败、发生条件和重要后果。只写“精度仍有提升空间”不是 gap。

### 先有靶再射箭

> 〔转写〕“先有靶再射箭这种就比较好一点，但是它难度也会高。”

理想顺序是：观察 failure、分析原因、定位现有机制缺陷，再推出方法。探索实验可以帮助发现靶，但正式主张必须重新冻结并确认。

### 看目标会议是否收这类工作

不仅看会议名称，还要核近年接收数量、相关 track、评审标准和问题类型。若会议很少收该类任务，即使技术可做，投稿风险也高。

### 与个人能力保持连续

博士建议尽量往计算机/AI 靠，同时保留点云、定位、机器人等已有领域语言。公开数据和算法主证据服务论文；无人机、SLAM 和嵌入式系统继续服务工程能力与问题直觉。

### 查重不等于 gap 死亡：找 gap 的方法 + AI 防御性

> 与「证伪式立项审计」互补：证伪防「硬造 gap」，本节防「AI 过度否决」。

- **一个 gap 可容纳多种方法**：查重发现「有人做过」，不等于 gap 已经死了。同一个 gap（如「边界分割不清」）可以有人用 CNN、有人换一种机制各自解决，每种都成立。判断 gap 是否死亡，问「这个失败是否还真实存在、还有没有被当前方法解决的侧面」，而不是「有没有人碰过」。
  - 博士原话：「别人做了你再做（即使换了方法）它也觉得你不行……事实上你换一种方法去解决它，其实也是成立的。」「一个 gap 会有很多很多人用同样的不同的方法去解决，是可以容纳很多方法的，而不是有人做了就已经结束了。」
- **找 gap 用「研究脉络 / 时间线」**：把顶刊顶会论文按「同一方向的先后演进」（如 24/25/26 年）梳理成一条线，比零散文献矩阵更能暴露真正前沿的 gap。
  - CCF-A 大佬原话：「让 agent 把各个顶刊顶会论文对于这个方向的前后逻辑梳理出来……一些真正很前沿的 gap 就会很明显。」「核心就是要找到真正有价值的问题，然后解决他。」
- **AI 的防御性会误杀方向**：AI 倾向把「有人做过」判定为「你不该做」，导致方向被过度否决。需要加入自己的判断、放宽松、阶段迭代。
  - 博士原话：「ai 也会有点苛刻……事实上没有这么多完整的创新，可以放宽松一点。」「刚起步，一步一步来。」「这也是我们之前讨论的一个阶段一个阶段迭代这样。」
  - 用户诊断：「我感觉现在 ai 的防御性决策越来越严重了，或许这就是经常做完可行性测试试验后否掉我们方向的原因。」

### 为箭找靶 vs 为靶找箭（立项前自查五条）

> 核心教训：团队 5 次方向变换都死在「拿一支先有的工程组合机制（箭），四处找能套上的任务（靶）」，而不是「先发现真 failure（靶），再推机制（箭）」。这是「先有靶再射箭」被倒置的后果。

立项前按五条自查，任一条亮红灯都可能说明又回到「为箭找靶」：

1. **先找靶，再射箭**：先实证一个真实、可量化的 failure（观察 failure → 分析机制 → 推出方法），再谈方法；没有 failure 先有机制，就是「为箭找靶」。（呼应「先有靶再射箭」）
2. **去术语测试**：把机制每个部件去掉术语，若每一步都有成熟现成替代品，就是工程组合，不是结构性矛盾。（呼应「去术语测试」）
3. **换任务前先问**：这是换了一个新靶，还是又拿同一支钝箭换靶？机制不变，换载体解决不了「箭钝」。
4. **警惕「机制发现 = 投降」**：当开始写「机制发现 / 可解释性」来救一个方法论文时，这是在研究「箭为什么射不中」，是投降，不是升级。
5. **严谨协议救不了起点错误**：预注册、止损、证据阶梯校准不了「箭钝」；起点错误要回到「先找靶」重做，不是靠加协议掩盖。

## Gap 锋利度：结构性矛盾还是工程直觉

查重回答“有没有人占”，锋利度回答“这条缝值不值得占”。

- **强 gap**：现有范式在某类问题上存在结构性缺陷，不改变机制无法解决。
- **弱 gap**：某处不足就补某处，属于自然工程直觉而非结构性缺陷。（例：分辨率不够就放大、局部没语境就加融合、教师不可靠就加权。）

### 去术语测试

把方法名和术语全部去掉。如果每一步都“太容易想到”，说明贡献可能只是组合。例（FocalAfford 场景）：

```text
现有模型 -> 局部放大 -> 加全局上下文 -> 只蒸馏更好的区域 -> 更准预测
```

### Reviewer 连环问

原则：把方法去术语后，reviewer 能否连续追问「为什么不用现成替代 X」？若每步都有成熟替代，当前设计就不是不可替代的机制。

例（3D affordance / FocalAfford 场景）：为什么不用 crop、更高分辨率、adaptive sampling、现有 local-global fusion、普通 uncertainty weighting、直接 GT reweight？

### 消融的反向信号

如果 proposal 主要篇幅都在证明“不是简单 trick”，这本身说明核心问题不够一眼重要。消融必要，但强 paper 的主线首先应正面解决清晰矛盾，而不是靠大量防御建立存在感。

### 应用层不等于方法层

downstream validation 能证明应用价值，不能独自回答方法为什么重要。接下游仿真器或平台（如 FlightBench、Aerial Gym、无人机仿真），不会让普通视觉改进自动升级为方法贡献。

### 结果导向与问题导向

- 弱：先有模块，再给模块寻找理由。
- 强：先发现量化 failure，再分析机制，最后推出干预。

把弱 gap 抬高，不是再加模块，而是重审根问题：先证明失败与某个可量化因素系统相关、并排除简单干预，才可能把问题从「工程直觉」上升为「结构性矛盾」。（例：FocalAfford 场景——证明性能与功能区域占比系统相关、排除简单提高分辨率，才上升为 global semantic understanding 与 local spatial precision 的冲突。）

## 可行性与资产

### Baseline 优先开源

> 〔会议〕“不开源的首先我们很难复现，其次它可能数据不一定是真实的，然后我们就只看开源的代码。”

优先代码、数据、权重和 evaluator 齐全的方法。只公开论文、没有可核验实现的工作可作相关工作，不能承担短周期主 baseline。

### 同任务资产迁移

公开数据通常能找到多个同任务模型；相近数据集可能只需调整输入输出。但“只需小改”是经验预期，必须通过 schema、标签、metric 和数据划分核验。

### 算力和周期

博士关注单卡 4090、2~3 天训练和短周期成本。创新越强往往实现风险越高，因此候选排序必须同时考虑技术新颖性、实验可行性和一个月内能否完成。

## 创新与贡献

### 博士的现实路线

> 〔转写〕“所谓的创新就是排列组合。”
> 〔转写〕“不是说一定要自己原创……因为你想到了一定有人做过。”

可行手法包括：插入、替换、升级模块；改变扫描机制；改造旧知识；组合成熟分支并设计新连接；迁移大模型或相邻领域成熟机制。

博士分享中的具体例子包括：把规整扫描改为锯齿或环状；用 PConv 替换普通卷积；把“风车卷积 4321”改造成连续高斯分布；从两个成熟模型各取一条分支，再以自设计连接交互。这些例子用于说明创新手法，不能脱离任务 failure 直接照搬。

这是一条投稿与执行经验，不表示任意拼接都具有学术价值。组合必须回应可观察问题，并战胜最简单组合 baseline。

### 一个模块一个贡献点

博士用“一个模块 = 一个贡献点”帮助学生组织工作；写作中应称 contribution，不自称 innovation。更稳妥的解释是：一篇论文只卖一个核心贡献，其下可以有问题发现、机制设计、评测协议三个子贡献，而不是三个无关模块。

### 先缝合有效，再创新

> 〔会议〕“先把成熟模型的一个模块缝进来，可以看到提点，然后再修改内部机制。”

这适合探索，但正式论文仍需证明：成熟模块为什么适合当前失败、直接组合是否足够、修改后的机制增加了什么不可替代的作用。

### 适中路线

本科生短周期的稳妥路线是：公开强 baseline + 成熟可迁移机制 + 一个任务特有的小改造。若简单方法已经恢复现象，应接受简单答案，不为了贡献数量继续叠模块。

## Idea 报告范式

博士偏好的结构：模型名 + 冒号式标题，而不是问句；正文包括背景、相关工作、gap、方法、三个 contribution、可用 baseline 和数据集。

高质量 idea 报告中最有价值的做法：

1. **一句话锚定具体缺陷**：不写泛泛的“局部区域困难”，而要指出现有机制在哪个计算环节没有把信息或计算送到需要的位置。
2. **诚实定位创新类型**：跨领域迁移 + 任务组合改良，不声称全新范式。
3. **预定义关键简单基线**：直接局部重渲染/蒸馏、GT 重加权等必须先比较。
4. **每阶段写问题和失败处理**：某组件不优于简单版本就删除该贡献。
5. **写清收缩路线**：三项均成立形成完整故事；只成立第一项则降级；第一项也不成立则停止。
6. **冻结、缓存、分阶段**：避免每个组合都完整训练。

Idea 报告是可证伪设计，不是实验结果。

## 证伪式立项审计

### 最高原则

> 〔SCI审计〕“尽最大努力证明每一个候选创新点已经被别人做过、创新不足、意义不足、实验不足，或者不值得投入。”

若系统检索后没有足以支撑目标档次的 gap，应直接停止，禁止为了完成任务硬造 gap。

### Related-work matrix

最近邻矩阵必须有：Similarity、Threat、核心差异、代码/数据、证据来源。高度相关工作至少阅读方法、实验和结论，不能只根据标题摘要填写。

### Gap Survival Table

```text
Candidate Gap | Closest Work | Difference | Novelty | Significance |
Technical Feasibility | Experimental Feasibility | Incremental Risk | Survive?
```

状态只用 `SURVIVE / WEAK / KILL`。博士任务书建议 Novelty 或 Significance 低于 6/10 原则上淘汰；分数是相对排序工具，不是录取概率。

### Top-10 最近邻与拒稿句

找最接近的约 10 篇工作，逐篇回答：“如果我是审稿人，会不会问你和它有什么本质区别？”同时写一句：如果今天直接投稿，最可能因为什么被拒？

### 投稿树

目标不是盲目最大化期刊档次，而是最大化截止时间前接收概率与期刊质量的乘积。为 A/B/C 目标写清 desk reject、一个月 reject、三个月 reject 和时间保险策略。期刊 scope、APC、分区和审稿时间必须区分官方事实、第三方统计和推断。

### 证据标准

不得编造 DOI 或论文，不根据标题猜方法，不把搜索摘要当全文证据，不根据二手网站断言期刊政策，也不从单篇论文推出整个领域不存在相关工作。对分区、APC、scope 和审稿时间，明确标记官方事实、第三方统计或推断；无法确认时写 `UNVERIFIED`。

## 历史反面教材

### 置信度可校准 LiDAR 地点识别

被否决：AI 偏好风险高，且相关问题已被近年工作直接研究。

### 质量条件控制的统一点云恢复

被否决：统一恢复、混合退化和输入质量自适应已有直接覆盖；轻量不是核心科学问题。

### Add-Move-Delete 顺序恢复

关键拒稿问题：顺序重要性只是被假设；若共享网络一次恢复达到同等效果，程序解析和顺序执行只是复杂度。还需面对脚本指纹、逆程序不唯一和组合爆炸。

### CUE-Loc 跨模态方向

跨模态定位赛道拥挤；不要把可信单线当整篇论文。更合理的是针对具体场景，在精度改良主线中把可信作为一个贡献，并回答为什么“判断是否接受”比“找到位置”重要。

### IJCNN 历史候选排名

早期候选曾包括置信度 LiDAR 地点识别、可变稀疏度点云恢复、UAV-卫星定位、VIO、UAV 小目标、仿真导航和 LiDAR-camera 检测。该排名只展示当时如何综合方向、算力和会议，不是今日有效的方向结论；其中置信度方向后来已被否决。

## 可直接使用的选题红队提示词

```text
请以试图拒稿的审稿人身份审查当前候选。先核最近邻正文和官方代码，再回答：
1. 一句话 gap 是否是结构性矛盾，还是工程直觉？
2. 去掉术语后，方法是否只是自然模块组合？
3. crop、重采样、重加权、普通 loss 或强 baseline 能否替代？
4. 最接近的 10 篇工作分别威胁哪条主张？
5. 数据是否真的能回答问题？
6. 最便宜的否定实验是什么？
7. 什么结果出现必须降级或停止？
8. 如果今天直接投稿，最可能因为什么被拒？

区分已核实事实、导师/博士经验、待验证假设和真实实验结果。没有证据时标 UNVERIFIED；不要为了完成任务硬造 gap。
```

## 经验冲突的统一解释

| 表面冲突 | 使用方式 |
|---|---|
| “创新是排列组合” vs “不能模块拼接” | 排列组合是探索手段；可观察 failure 和简单对照决定其是否成为贡献。 |
| “一个模块一个贡献点” vs “一篇论文只卖一个贡献” | 多个子贡献必须服务同一核心主线。 |
| “20% 不行，100% 也不行” vs 子集不代表全量 | 20% 用于快速止损，不作数学证明；通过后全量确认。 |
| “正常人不看随机种子” vs 可复现要求 | 历史意见不替代执行协议；正式筛选的 seed 下限按 `docs/02_实验设计与筛选.md`，记录所有 seed、不挑最好结果。 |
| “先缝合有效再创新” vs “先有靶再射箭” | 探索允许成熟模块试验；正式主张必须回到 failure 并在冻结协议确认。 |
| “先写论文再补实验” vs 不把计划写成结果 | 早搭骨架发现缺口，但明确占位，不伪造数字。 |
| 下游验证重要 vs 应用层不是方法层 | 下游证明价值，不能单独证明核心机制创新。 |
| “gap 要锋利” vs “一个 gap 可容纳多种方法” | 锋利判断的是**问题级**（结构性矛盾，可被多种方法攻击）；“有人做过”只说明**方法级**被碰过，不等于问题级死了。 |

## 最终检查

在投入完整实验前，只问七件事：

1. 最近邻是否核到正文或官方代码？
2. gap 是否一句话可测，并经过去术语与 reviewer 连环问？
3. 数据是否能构造决定性比较？
4. 官方 baseline 是否已通过单样本和 20% 工程筛选？
5. 最简单替代方案是否写进实验？
6. 失败、降级和停止路线是否明确？
7. 这项工作是否能在时间、算力和个人解释能力内完成？

任一关键项答不上来，先补证，不继续增加模块。

## 博士论文方法论补遗（选题）

### 选题定位：先用「框架/轴」切子问题，再收敛

博士论文的共同做法是先用一个**显式定位框架/轴**把大领域切开，再收敛到具体 RQ。例：三层表征（Thomas）、四层金字塔（Rosinol）、scalability×task-complexity 两轴（Chang）、data/brain/body（Johnson Wang）、感知/策略/规划（Fang）。规则：**RQ 数 = 贡献数 = 章节数**，一一对应；每个子问题可独立交付，单点失败不拖垮全局。这是「gap 锋利度」之前缺失的一环：先有框架给选题定位，再谈单个 gap 尖不尖。

### 显式 scoping：公开划定「我不做哪部分」

比「去术语测试」更进一步：不只说人话，还要**公开声明边界**。例：Rosinol「whenever we mention SLAM we refer to visual-inertial SLAM, in contrast to LiDAR-based SLAM」；Thomas 明确区分 representation vs data type。选题时先写「我明确不做哪部分」，避免 reviewer 拿边界外工作来攻。

### 用具体 motivating example 锚定抽象 gap

抽象 gap 要落到一个**可观察、可失败的具体场景**才能判定「真问题」。例：Fang 用「往微波炉塞东西，门没全开、杯子挡门」落地抽象的「通用具身 agent」。抽象 gap 配一个具体失败场景；没有具体场景的 gap 先别立项。

### 「结构性矛盾」= 现有方法的结构性假设 vs 数据本质属性

六篇几乎都用这个三段论：CNN 假设网格 vs 点云无序（Thomas / Yue Wang）；foundation model 假设互联网规模数据 vs 机器人数据稀缺（Fang / Johnson Wang）；几何重建 vs 决策需要语义（Chang / Rosinol）。写 gap 用「结构性假设 → 本质属性 → 缺口」，比「工程直觉」有可观察锚点。

### 修正：「gap 要锋利」与「查重≠gap 死」作用于不同层面

见「经验冲突的统一解释」：问题级 gap（结构性矛盾）可容纳多种方法；方法级 novelty 被覆盖才死。两者不矛盾，只是层级不同。

## Proposal 审计：PACE-PC 案例

PACE-PC 报告曾把“问题 - gap - 方法 - baseline - 数据集”写得很完整，但完整叙事仍只是候选设计。这个案例保留如下，因为它展示了如何拆开已有事实与新主张。

### 当时能够确认的基础

- SuperPC、PQDT 等统一点云恢复方向存在；
- DWCNet/CPCCD、PointMAC 等相关数据或方法线索存在；
- ZFusion、复合退化图像恢复等邻域机制存在；
- 部分工作只能确认到预印本或代码线索，不能冒充已发表顶会。

“论文存在”只支持方向背景，不自动支持 PACE-PC 的偏序、程序监督或组合泛化主张。

### 尚未成立的八项主张

1. 点云复合退化存在可学习偏序；
2. Add/Move/Delete 足以覆盖目标退化；
3. 可以获得可靠的退化程序轨迹监督；
4. 能从二阶组合泛化到反序和三阶组合；
5. 局部 UOT 与当前编辑语义匹配；
6. 单卡 4090 可完成全部训练；
7. 新建 CPCCD-Program 与 seen/unseen 划分不会泄漏；
8. “首次”“真正缺少”等措辞已有系统查重支持。

### 四个技术风险

- **顺序效应可能是脚本指纹**：离散采样、随机参数和归一化可能制造表面非交换性。
- **逆程序不唯一**：同一退化点云可能来自多条等价路径，强制唯一监督会引入错误标签。
- **benchmark 可能压过方法**：若真正贡献是组合划分，模型与协议可能都不完整。
- **实验组合爆炸**：原子、顺序、强度、阶数、数据集和 baseline 会迅速超出小论文周期。

### 最小立项检查

只有最近邻查重、退化定义、顺序最小反例、单卡实测预算和导师技术评审均站住，才值得进入 baseline。若顺序效应不稳定，应停止，而不是因为 proposal 已写完整就继续投入。

这个案例的通用结论是：题目叙事、相关论文和合理类比必须与尚未验证的机制主张分开书写。
