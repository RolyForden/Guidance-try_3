# 失败模式库（FAILURE PATTERNS）

> 用途：长期积累「方向 / 方法为什么会失败」的模式。每踩一次坑，提炼成一条可复用的模式，避免重蹈。
> 原则：只记根因，不记情绪；只记「已证实的失败」，不记「猜测的失败」。每条必须能回到具体项目/决策。
> 边界：本文件只记**已证实的失败模式** + 由它们提炼的准则；正面规则（怎么写锚、怎么做实验）放各阶段文档 `01`–`04`，此处只留准则并链接过去。

## 怎么用

- **立项前**：对照一遍，问「我是不是又踩了某条 FP」。
- **复盘时**：每踩一个新坑，补一条 `FP-00X`（只记已证实的、只记根因）。

## 记录格式

每条失败模式固定四字段：

- **现象**：表面发生了什么（换了几次方向、做了一大圈被否……）
- **根因**：真正的原因（不是「赛道拥挤」这种症状，而是「起点错误」这种根因）
- **教训**：可复用的一句话准则
- **案例**：触发这条模式的具体项目 / 方向（链接到决策或复盘）

## FP-001 为箭找靶

- **现象**：FocalAfford 一条线换了 5 次任务（3D affordance → 航空分割 → 视觉里程计 → 无人机巡检 → 机制发现），每次都被否。
- **根因**：拿一支「先有箭」的工程组合机制（局部放大 + 全局融合 + 选择性蒸馏，去术语后全是自然工程动作），四处找能套上的任务；而不是先发现一个真实 failure，再由 failure 推机制。查重撞车只是症状，不是根因。
- **教训**：先找靶再射箭；机制不变，换任务载体解决不了「箭钝」。
- **案例**：外部仓库 Guidance-try_1 [复盘（固定版本）](https://github.com/RolyForden/Guidance-try_1/blob/534d2983ed97b086b0cdb267b8023e0f18cc61d7/projects/20260902-CCFC%E9%80%89%E9%A2%98/%E5%A4%8D%E7%9B%98.md)，记录 FocalAfford → FocalInspect → CAGE 换题链。不是母本内文件；需要该私有仓库访问权限。

## FP-002 缺锚

- **现象**：换了 8 次方向、每次都「被否」，却说不出到底哪一层坏（靶假 / 箭钝 / 测坏 / 训练不足）；每次换向的触发都是「查重撞车」「这是早期窗口」这类**外部信号**，没有一次来自自己测出的 failure。
- **根因**：没有「锚」——从立项起就没有一个真实、可量化、可复现、且排除简单解释的 failure。**没有靶，所有失败长得一样（都叫「被否」），于是无法归因、只能换；而换方向又让锚更建不起来，形成循环。**
- **教训**：立项前先造锚（见 `01_选题与立项.md` 的「锚」节）；换向只由内部实证触发，查重只用于排序；失败强制过归因表（靶假 / 箭钝 / 测坏 / 训练不足），说不出就别换向、去补锚。
- **案例**：同上 Guidance-try_1 固定版本复盘，历史记录的 8 个方向判断。不是母本内部项目。

## FP-003 改变 estimand（换数据集 = 换了被测的量）

- **现象**：核心科学问题没变、技术假设没变，但为了找“能支持路线的失败”而连续换载体；每个数据集都做了一点，却没有一个对第一环假设做过干净的因果检验。
- **根因**：把“换数据集”当成“同一问题换数据”，忽略了操作化研究问题（“局部”的定义、可用视觉、遮挡、视角、输出空间）已经变了 → 真正测量的对象（estimand）变了。
- **教训**：换载体前先问“我测的还是不是同一个量”；先在一个可控载体上把最窄的一环打穿，再谈换载体。
- **案例**：外部仓库 Guidance-try_2 [历程与停滞点（固定版本）](https://github.com/RolyForden/Guidance-try_2/blob/12004da525d25d8fa3212bf965fb404e1e6ad0d8/projects/20260922-FocalAfford/FocalAfford_%E5%8E%86%E7%A8%8B%E4%B8%8E%E5%81%9C%E6%BB%9E%E7%82%B9_20261003.md)。三个载体涉及不同测量条件；具体推断边界以阶段终止复盘为准。不是母本内文件，需要原仓库权限。

## FP-004 选了一个测不出假设的载体

- **现象**：换了多个数据集/载体做同类实验，结果始终是“未判定 / 不涨”，却误以为是方法的问题。
- **根因**：**载体（数据 + 任务/标注定义 + 评测口径）不能把假设放进一个可测的状态**——信号要么不在数据里，要么被任务/口径搅浑。三处常见部位：
  1. **数据里没有这个信号**：LASO 每物体仅 2048×3 XYZ、渲染“颜色”由坐标生成（伪 RGB）→ “局部视觉”根本无可测信号；
  2. **任务/标注定义盖住信号**：OpenAD 同一 affordance 在 train/val 用**同义不同名**（`grasp`/`grab`）→ “换名”主导，val 名 mIoU 0.144 vs train 名 0.414；
  3. **评测口径盖住信号**：SceneFun3D 单帧 4/10 vs 真值选帧多帧 oracle 7/10；官方 mask-IoU evaluator vs 内部 precision-AP50，口径不同不可比。
- **教训**：立项前先问“**这个载体能不能测出我要验的假设？信号真的在数据里、能被任务显出来、能被口径量出来吗？**”测不出就先换，别在上面反复做实验。**载体 ⊃ 数据集**：数据集只是载体的一块。
- **案例**：外部仓库 Guidance-try_2 [阶段终止复盘（固定版本）](https://github.com/RolyForden/Guidance-try_2/blob/12004da525d25d8fa3212bf965fb404e1e6ad0d8/projects/20260922-FocalAfford/%E9%98%B6%E6%AE%B5%E7%BB%88%E6%AD%A2%E5%A4%8D%E7%9B%98_20261006.md)。博士对载体敏感性的意见是经验判断，不替代各实验的证据边界。不是母本内文件，需要原仓库权限。

## 由模式提炼的准则

1. **立项前先造锚**：一个可量化、可复现、能排除 crop / 分辨率 / 歧义等简单解释的 failure；没有就不立项。
2. **换向只由内部实证触发**；查重 / 热度只用来给候选**排序**，不判决生死。
3. **每个失败强制过归因表**：靶假？箭钝？测坏？训练不足？说不出 = 没锚 → 不许换向，回去补锚。
4. **一个实现失败只否实现；要否方向，必须多个「异质」实现共同失败。**
5. **四层写清**：靶 / 箭 / 实现 / 实验设计——每次复盘标明动的是哪一层。
6. **先打穿最窄的一环**：把路线拆成 H1/H2/H3，冻结下游，先对 H1 做 oracle 反事实检验；换载体会改变被测的量，不能代替 H1 检验。
7. **先扎论文底座（参照锚）**：以 1–2 篇**读懂、能复现、能逐模块解释**的论文为参照锚（与“失败锚”配套）；起点从论文的 limitation 来。写不出“我以〔A〕+〔B〕为底座……”就不开工。
8. **选载体前先查敏感性**：数据 / 任务口径 / 评测口径能不能把假设放进一个“可测、可显、可量”的状态？不能就先换，别在上面反复做实验。
9. **“盲区条件”是候选靶，不是已证靶**：“baseline 没为条件 X 设计过” **≠** “它一定在 X 上失败”；先按 `docs/02_实验设计与筛选.md` 做 oracle / H1 必经性检查，证明真失败、且抗便宜替代，再上模块。
