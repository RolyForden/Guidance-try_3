# 论文底座启动指令（给执行 agent：自动起草 → 你只审批）

> **起手式（你只说这一句）**：「读 `templates/base_paper_kickoff.md` 并照做：论文 = ___；其余你自己完成，做完把草稿给我审。」
> 效果：agent 先读正文与官方代码，起草底座档案和复现计划；你确认后才运行，再用真实结果补齐档案。红线见根 `AGENTS.md`。

---

你是本仓库的执行 agent。按以下步骤**严格顺序**执行；**未获确认前不运行模型评测或训练，不动 GPU，不启动大文件下载。** 阅读、代码核查与资源估算可先做；已有明确授权只覆盖获批的范围，不自动覆盖候选筛选。

1. **读**：`AGENTS.md`、`docs/01_选题与立项.md`「论文底座」、`templates/base_paper.md`，以及用户给的论文。
2. **核**：读正文与官方代码，固定 commit，核查权重、数据、evaluator 与单卡资源。缺权重、必须训练才能复现时如实写明，不把训练隐藏成评测。
3. **起草**：按 `templates/base_paper.md` 写项目 `idea/base_paper_<简称>.md`；未运行的 §1 标“未运行，待批准复现”，其他无法核实项写“待确认 + 缺口”，不编数字。按 `templates/experiment_kickoff.md` 起草项目 `experiments/<实验名>/experiment.md`，类型写“底座复现”，冻结数据范围、命令、判据和预算。
4. **只交草稿**：一页说明论文数字、限制证据、拟复现范围、是否需训练与 blocker，停下等确认。底座复现允许使用未完成的底座草稿作输入；这是补齐 §1 的唯一前置例外，不能借此启动候选实验。
5. **获批后复现**：按冻结协议执行，遇 blocker 停报。原始结果回填底座档案 §1，补齐 §0–§6，项目 README 链接档案、协议和结果；未达到论文量级就保留差异，不宣称底座已就绪。
6. **底座就绪后**才起草候选筛选协议，另行审批。完整底座档案与实证锚仍是候选开跑前提；执行者不 commit/push。
