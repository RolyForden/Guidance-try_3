## 开始本仓库的课题

1. **讨论方向**：使用上面的起手式，先明确约束与底座论文候选，不预建题目或开实验。
2. **建项目骨架**：确定题目名称后，在本仓库运行 `.\scripts\new_topic.ps1 -Name "题目名称" -Venue "候选会议" -Deadline "YYYY-MM-DD"`，自动生成项目入口三文件；在本 README 的“当前项目”中链接它。
3. **工作**：在 `projects/<日期>-<题目>/` 里写 idea、跑实验、写论文；项目 README 是唯一状态入口，实验先交草稿审批。
4. **回传经验**：跨课题可复用的改进经审查后整合回母本，不把本课题材料搬进母本。

课题内的实际底座档案放 `idea/base_paper_<简称>.md`；实验冻结记录放 `experiments/<实验名>/experiment.md`，交付放该目录 `delivery/`；稿件放 `paper/`。这些是项目内路径，均由项目 README 链接，`templates/` 保持空白。执行者不直接改母本，主研究者审查回传后整合。

`scripts/validate_project.ps1` 只校验三个项目入口文件与必要标题，不代表底座就绪、协议获批或证据已审查；提交前仍需逐项核查实际档案、引用与交付。

## 文件边界

## 默认工作方式

1. 先把研究问题、可观察 failure 和停止条件写清楚；
2. 查最接近、最可能覆盖主张的论文与官方代码；
3. 先做最便宜、最可能推翻假设的检查；
4. 证据支持后才扩大实验或设计方法；
5. 只记录改变研究判断的事实，避免为流程制造文档。

## 目录

- `AGENTS.md`：不可妥协的研究、协作与文件归属规则（含选题三句自查）；
- `routes/`：各阶段**入口**——`选题.md` / `实验.md` / `写作.md`；开某阶段会话语时先读对应路由（只做指向，内容在被指向的文件里）；
- `projects/`：实际研究项目，确定题目后由 `new_topic.ps1` 创建；
- `docs/`：按阶段分篇——`01_选题与立项.md`、`02_实验设计与筛选.md`、`03_写作与投稿.md`、`04_协作与Agent.md`；`docs/选题gap审计规则.md` 是选题查重时执行的 Gap 合法性审计规则；`docs/FAILURE_PATTERNS.md` 积累失败模式；`docs/fields/` 放每个长期领域的 Frontier Map（`_模板.md` 是模板，[3D affordance 历史示例](docs/fields/3D-affordance-grounding.md)已冻结，不提供当前方向推荐）；
- `templates/`：项目、证据、决策和实验记录模板（实验记录含 Prediction / Confidence / Actual 判断校准）；
- `scripts/`：`new_topic.ps1`（建项目骨架）、`validate_project.ps1`（校验项目入口）。

判断文件位置时先问：它是否只服务于一个课题？如果是，就放入本仓库对应的 `projects/<日期>-<课题名>/`，不要放在根目录或 `docs/`，也不要回传进母本。
